یک **اشتراک** (subscription) یک URL واحد است که همه‌ی پیکربندی‌های یک کلاینت را
برمی‌گرداند. برنامه‌های کلاینت آن را به‌صورت دوره‌ای تازه‌سازی می‌کنند، بنابراین وقتی
یک ورودی را تغییر می‌دهید، کلاینت‌ها این تغییر را به‌صورت خودکار دریافت می‌کنند. سرور
اشتراک به‌عنوان یک سرور **جداگانه** از پنل اجرا می‌شود.

## فعال‌سازی و پیکربندی

سرور اشتراک به‌صورت **پیش‌فرض روشن** است (`subEnable`). آن را در تنظیمات اشتراک
پنل پیکربندی کنید:

| Setting       | Default | Meaning                                                         |
| ------------- | ------- | --------------------------------------------------------------- |
| `subPort`     | `2096`  | پورت گوش‌دادن (جدا از پنل).                                      |
| `subListen`   | _(همه)_ | آدرس اتصال (bind).                                              |
| `subPath`     | _(تصادفی برای هر پنل)_ | مسیر پایه برای URLهای خام اشتراک.                  |
| `subDomain`   | _(هیچ)_ | میزبان عمومی؛ اگر تنظیم شود، سرور فقط به همان Host پاسخ می‌دهد.   |
| `subCertFile` / `subKeyFile` | _(هیچ)_ | گواهی و کلید TLS — هنگام تنظیم، سرور **HTTPS** ارائه می‌دهد. |
| `subEncrypt`  | `true`  | بدنه‌ی خام اشتراک را با base64 رمزگذاری می‌کند.                   |
| `subUpdates`  | `12`    | بازه‌ی پیشنهادی تازه‌سازی (ساعت) که به کلاینت‌ها ارسال می‌شود.    |

یک URL اشتراک به این شکل است:

```text
https://<sub-host>:<sub-port>/<sub-path>/<sub-id>
```

که در آن `<sub-id>` همان **Sub ID** کلاینت است.

همان Sub ID در چند قالب روی مسیرهای مختلف ارائه می‌شود — فهرست **Base64** در
`subPath` و پیکربندی **JSON** (Xray-json) در مسیر JSON. URLها را بسازید و هر دو
بدنه را اینجا پیش‌نمایش کنید:

## قالب‌های خروجی

**قالب بر اساس مسیر انتخاب می‌شود** و هرکدام کلید فعال‌سازی مخصوص خود را دارند:

| Format                | Path      | Enabled by       | Output                                              |
| --------------------- | --------- | ---------------- | --------------------------------------------------- |
| **لینک‌های خام**       | `subPath`      | همیشه (اگر روشن باشد) | فهرستی از لینک‌های `vless://`، `vmess://`، … (هنگام فعال‌بودن `subEncrypt` با base64 رمزگذاری می‌شود). |
| **JSON**              | `subJsonPath`  | `subJsonEnable`  | پیکربندی(های) کامل کلاینت Xray.                      |
| **Clash / Mihomo**    | `subClashPath` | `subClashEnable` | پروفایل YAML.                                        |

فقط ورودی‌های فعالی که از **VLESS، VMess، Trojan، Shadowsocks، WireGuard، AmneziaWG، MTProto، TUIC یا Hysteria2**
استفاده می‌کنند در یک اشتراک ظاهر می‌شوند و بر اساس شاخص sub-sort آن‌ها مرتب می‌شوند (TUIC و AmneziaWG در لینک‌های خام و پروفایل‌های Clash/Mihomo گنجانده می‌شوند اما از اندپوینت‌های JSON حذف می‌شوند؛ MTProto در لینک‌های خام گنجانده می‌شود). درخواست `subPath` همراه با هدر `Accept: text/html` (یا `?html=1`) به‌جای بدنه‌ی خام،
یک صفحه‌ی اطلاعات خوانا برای انسان برمی‌گرداند.

### اتصال مستقیم سایت‌های داخلی

**تنظیمات ← اشتراک ← اتصال مستقیم سایت‌های داخلی** (`subLocalDirect`) یک کشور می‌گیرد:
کد ISO 3166-1 alpha-2 مانند `ir` یا `ru`؛ خالی یعنی خاموش. برنامه‌های کاربران
سایت‌های همان کشور را مستقیم باز می‌کنند و بقیه را از VPN می‌فرستند؛ بانک‌ها،
درگاه‌های دولتی و فروشگاه‌هایی که نشانی خارجی را نمی‌پذیرند با VPN روشن هم کار
می‌کنند. به‌طور پیش‌فرض خاموش است و پنل به‌روزشده همان خروجی قبلی را می‌دهد.

قوانین به ترتیب بررسی:

1. نشانی‌های خصوصی و شبکهٔ محلی: مستقیم.
2. فهرست **همیشه از طریق VPN** (`subLocalDirectProxy`): از پروکسی. این فهرست پیش از
   کشور بررسی می‌شود، چون برخی سرویس‌های خارجی داخلی به نظر می‌رسند: بازه‌های نشانی
   Telegram در پایگاه‌های geoip روسی ثبت شده‌اند و Google ویدیو را از کش‌های درون
   اپراتورهای محلی می‌دهد. فهرست پیش‌فرض شامل Telegram (دامنه‌ها و بازه‌های
   IPv4/IPv6)، YouTube، Instagram و Facebook، WhatsApp، Discord، OpenAI و Anthropic
   است. قابل ویرایش است: هر خط یک دامنه یا بازهٔ IP (حداکثر ۲۰۰)؛ خالی‌کردن کادر
   فهرست پیش‌فرض را برمی‌گرداند.
3. دامنه‌های ملی کشور: مستقیم. برای `ru`‏ `.ru`، `.su` و `.рф`؛ برای `by`‏ `.by` و
   `.бел`؛ برای `kz`‏ `.kz` و `.қаз`؛ برای `gb`‏ `.uk`؛ برای کدهای دیگر دامنهٔ
   دوحرفی همان کشور.
4. دستهٔ آمادهٔ کشور در `geosite`: مستقیم، اگر در `geosite.dat` خود پنل باشد:
   `category-ir`، `category-ru` و مانند آن؛ برای چین `cn` یا `geolocation-cn`.
5. `geoip` کشور: مستقیم، اگر کشور در `geoip.dat` پنل باشد.
6. بقیه: از پروکسی.

| قالب | کلاینت چه می‌گیرد |
| --- | --- |
| **JSON** | قوانین در `routing.rules` پیش از قانون عمومی، با `domainStrategy: IPIfNonMatch`. |
| **Clash / Mihomo** | قوانین `IP-CIDR` (`no-resolve`)، `DOMAIN-SUFFIX`، `GEOSITE` و `GEOIP` پیش از `MATCH,PROXY`. پروفایل Clash for Windows همان است بدون `GEOSITE`. |
| **Happ، INCY** | پروفایل مسیریابی در هدر پاسخ `Routing`، قوانین پروکسی پیش از مستقیم؛ Happ هدر `Routing-Enable: true` را هم می‌گیرد. |
| **Shadowrocket** | فایل قوانین در `<نشانی اشتراک>/shadowrocket.conf` که در صفحهٔ اشتراک پیشنهاد می‌شود: آن را در زبانهٔ Config اضافه کنید و Global Routing را روی Config بگذارید. فقط دامنه‌های ملی و `GEOIP`؛ Shadowrocket قانون `GEOSITE` ندارد. |
| **لینک‌های خام (Base64)** | هیچ. فهرست لینک‌ها نمی‌تواند قانون مسیریابی حمل کند؛ برنامه‌هایی که فقط لینک می‌گیرند به اشتراک JSON یا تنظیمات مسیریابی خودشان نیاز دارند. |
| **AmneziaWG، WireGuard** | هیچ. این تونل‌ها فقط با پیشوندهای IP (`AllowedIPs`) مسیریابی می‌کنند و یک کشور هزاران پیشوند دارد که پیوسته تغییر می‌کنند. |

پروفایل مسیریابی‌ای که خودتان برای یک قالب تنظیم کرده‌اید در همان قالب اولویت دارد.
**پروفایل مسیریابی JSON** (`subJsonRoutingRules`) در سندهای JSON و در هدر `Routing`
جای این قوانین را می‌گیرد و پروفایل مسیریابی Happ در هدر. قوانین سفارشی Clash پیش از
این قوانین قرار می‌گیرند و اگر `MATCH` خودشان را داشته باشند جای آن‌ها را می‌گیرند.
فیلد قدیمی قوانین JSON (`subJsonRules`) همچنان جلوتر می‌ماند.

کشور، فهرست و پایگاه‌های geo هنگام شروع سرور اشتراک خوانده می‌شوند؛ پس تغییر پس از
راه‌اندازی دوبارهٔ پنل اعمال می‌شود. دسته‌ها با پایگاه‌های پنل سنجیده می‌شوند، چون
هستهٔ کلاینت کل پروفایلی را که دسته‌ای ناموجود در پایگاهش دارد رد می‌کند؛ کلاینتی با
پایگاه غیرمعمول ممکن است باز هم دسته‌ای را نداشته باشد. این تنظیم برای کل پنل یکی
است: کشور جداگانه برای هر کلاینت وجود ندارد و پنل کشور را از نشانی درخواست‌کنندهٔ
اشتراک حدس نمی‌زند و هیچ سرویس geo بیرونی را صدا نمی‌زند.

### Base64 vs JSON

بدنه‌ی **Base64** صرفاً همان لینک‌های اشتراک‌گذاری است که با خط جدید به هم پیوسته و
با standard-base64 رمزگذاری شده‌اند (با `subEncrypt` قابل تغییر است). بدنه‌ی **JSON**
هر کلاینت را در یک پیکربندی کامل کلاینت Xray می‌پیچد — یک اسکلت ثابت (ورودی‌های محلی
SOCKS/HTTP روی 127.0.0.1، DNS، مسیریابی، policy) به‌علاوه‌ی یک outbound از نوع `proxy` که به ورودی
اشاره می‌کند. 3x-ui **برای یک کلاینت یک شیء پیکربندی واحد و برای چند کلاینت یک آرایه**
تولید می‌کند، از فرم تخت `settings` در outbound استفاده می‌کند
(`address`/`port`/`id`، `level: 8`) و `sockopt` را از `streamSettings` حذف می‌کند.

## هدرهای پاسخ

اشتراک‌ها هدرهای استانداردی برمی‌گردانند که برنامه‌های سازگار آن‌ها را می‌خوانند:

- **`Subscription-Userinfo`** — `upload`، `download`، `total` (بایت؛ `total=0`
  یعنی نامحدود) و `expire` (ثانیه‌های Unix).
- **`Profile-Update-Interval`** — بازه‌ی تازه‌سازی برحسب ساعت (`subUpdates`).
- **`Profile-Title`**، **`Support-Url`**، **`Profile-Web-Page-Url`**،
  **`Announce`** — برندینگ اختیاری که برخی کلاینت‌ها نمایش می‌دهند.

### لینک صفحه پروفایل

در تنظیمات **سابسکریپشن ← پروفایل**، گزینه **صفحه پروفایل** (`subProfileMode`)
لینک را برای همه کلاینت‌های اشتراک کنترل می‌کند:

- **بدون لینک** (`none`، پیش‌فرض) — هدر `Profile-Web-Page-Url` ارسال نمی‌شود.
- **صفحه اشتراک داخلی** (`builtin`) — لینک صفحه اشتراک داخلی ارائه می‌شود.
- **وب‌سایت سفارشی** (`custom`) — آدرس `subProfileUrl` استفاده می‌شود؛ اگر خالی باشد، هدر ارسال نمی‌شود.

**پس از ارتقا:** اگر `subProfileMode` هنوز تنظیم نشده و مقدار قبلی `subProfileUrl`
خالی یا فقط شامل فاصله باشد، به‌جای لینک خودکار صفحه داخلی، حالت **بدون لینک**
انتخاب می‌شود. آدرس سفارشی غیرخالی قبلی در حالت **وب‌سایت سفارشی** حفظ می‌شود.

برای بازگرداندن لینک قبلی، در همین بخش **صفحه اشتراک داخلی** را انتخاب و تنظیمات
را ذخیره کنید. این صفحه آدرس‌های اشتراک و پیکربندی گره‌ها را آشکار می‌کند، حتی
برای اشتراک‌های رمزگذاری‌شده Happ.

## قالب‌های سفارشی صفحه

برای برندینگ صفحه‌ی HTML اشتراک، `subThemeDir` را به یک پوشه‌ی حاوی قالب سفارشیِ
صفحه‌ی اطلاعات اشاره دهید. توضیح (remark) هر کلاینت روی هر لینک کاملاً قابل
قالب‌بندی است — به [لینک‌های اشتراک‌گذاری ← متغیرهای remark](/docs/config/share-links#remark-template-variables) مراجعه کنید.

<Callout type="info">
  سرور اشتراک را پشت TLS قرار دهید (با تنظیم `subCertFile`/`subKeyFile`، یا یک
  [پروکسی معکوس](/docs/operations/reverse-proxy)) تا محتوای اشتراک در حین انتقال
  افشا نشود.
</Callout>
