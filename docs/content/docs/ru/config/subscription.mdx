**Подписка** — это единый URL, который возвращает все конфигурации клиента.
Клиентские приложения периодически обновляют его, поэтому при изменении
входящего соединения клиенты подхватывают изменения автоматически. Сервер
подписок работает как **отдельный** сервер от панели.

## Включение и настройка

Сервер подписок **включён по умолчанию** (`subEnable`). Настройте его в
параметрах подписки панели:

| Параметр      | По умолчанию | Назначение                                                  |
| ------------- | ------- | --------------------------------------------------------------- |
| `subPort`     | `2096`  | Порт прослушивания (отдельный от панели).                       |
| `subListen`   | _(все)_ | Адрес привязки.                                                 |
| `subPath`     | _(случайный для каждой панели)_ | Базовый путь для необработанных URL подписок. |
| `subDomain`   | _(нет)_ | Публичный хост; если задан, сервер отвечает только для этого Host. |
| `subCertFile` / `subKeyFile` | _(нет)_ | Сертификат + ключ TLS — когда заданы, сервер работает по **HTTPS**. |
| `subEncrypt`  | `true`  | Кодировать тело необработанной подписки в base64.               |
| `subUpdates`  | `12`    | Рекомендуемый интервал обновления (часы), отправляемый клиентам. |

URL подписки выглядит так:

```text
https://<sub-host>:<sub-port>/<sub-path>/<sub-id>
```

где `<sub-id>` — это **Sub ID** клиента.

Один и тот же Sub ID отдаётся в нескольких форматах по разным путям — список
**Base64** по `subPath` и конфигурация **JSON** (Xray-json) по пути JSON.

## Форматы вывода

**Формат выбирается по пути**, у каждого свой переключатель включения:

| Формат                | Путь      | Включается       | Вывод                                               |
| --------------------- | --------- | ---------------- | --------------------------------------------------- |
| **Необработанные ссылки** | `subPath`      | всегда (если включён) | Список ссылок `vless://`, `vmess://`, … (закодированных в base64, когда включён `subEncrypt`). |
| **JSON**              | `subJsonPath`  | `subJsonEnable`  | Полные клиентские конфигурации Xray.                |
| **Clash / Mihomo**    | `subClashPath` | `subClashEnable` | YAML-профиль.                                       |

В подписке появляются только включённые входящие соединения, использующие
**VLESS, VMess, Trojan, Shadowsocks, WireGuard, AmneziaWG, MTProto, TUIC или Hysteria2**, упорядоченные по их индексу
сортировки подписки (TUIC и AmneziaWG включаются в raw-ссылки и профили Clash/Mihomo, но исключаются из JSON-конфигов; MTProto включается в raw-ссылки). Запрос `subPath` с заголовком `Accept: text/html` (или
`?html=1`) возвращает удобочитаемую информационную страницу вместо
необработанного тела.

### Группа Auto в Clash/Mihomo

Если включено **Настройки → Подписка → Группа Auto** (`subClashAutoGroup`), в
профили Clash и Mihomo добавляется группа `Auto` со всеми серверами подписки.
Приложение само проверяет каждый сервер через туннель и переходит на рабочий:
заблокированный или упавший сервер стоит пользователю минуту, а не письма в
поддержку. `Auto` — первый пункт группы выбора `PROXY` и выбор по умолчанию;
сервер там по-прежнему можно выбрать вручную.

| Настройка | Ключ | По умолчанию |
| --- | --- | --- |
| Режим: **Самый быстрый** (`url-test`) или **Первый рабочий** (`fallback`, по порядку подписки) | `subClashAutoGroupType` | `url-test` |
| Адрес проверки (должен отвечать 204/200 через туннель) | `subClashAutoGroupUrl` | `http://www.gstatic.com/generate_204` |
| Интервал проверки, секунды (10–86400) | `subClashAutoGroupInterval` | `300` |
| Допуск, мс (только `url-test`; не даёт прыгать из-за колебаний задержки) | `subClashAutoGroupTolerance` | `50` |

`Auto` появляется, только если в подписке два сервера или больше; информационный
узел подписки в группу не входит. Сервер с названием `Auto` переименовывается,
чтобы профиль оставался рабочим. Свои правила маршрутизации Clash и удалённые
шаблоны могут направлять трафик в `Auto` (например, `MATCH,Auto`): тогда группа
выдаётся и для одного сервера, и при выключенном переключателе, а шаблон со своей
группой `Auto` заменяет созданную панелью.

На новых установках переключатель включён. Панель, обновлённая с версии без этой
группы, держит его выключенным, пока администратор не включит: у подписчиков
после обновления подписки не появится новый выбор по умолчанию. У JSON-подписок
Xray свой балансировщик; профили sing-box still-ui не выдаёт.

### Местные сайты напрямую

**Настройки → Подписка → Настройки панели → Местные сайты напрямую**
(`subLocalDirect`) — это страна: код ISO 3166-1 alpha-2, например `ru` или
`ir`; пусто — выключено. Приложения клиентов открывают сайты этой страны
напрямую, а всё остальное отправляют через VPN: банки, Госуслуги и
маркетплейсы, которые не пускают с иностранных адресов, работают при
включённом VPN. По умолчанию выключено; обновлённая панель отдаёт ровно то же,
что и раньше.

Правила, в порядке проверки:

1. Частные и локальные адреса — напрямую.
2. Список **Всегда через VPN** (`subLocalDirectProxy`) — через прокси. Он
   проверяется раньше страны, потому что часть иностранных сервисов выглядит
   местными: диапазоны адресов Telegram числятся в базах geoip российскими, а
   Google отдаёт видео с кэшей внутри местных провайдеров. Во встроенном списке
   Telegram (домены и его диапазоны IPv4/IPv6), YouTube, Instagram и Facebook,
   WhatsApp, Discord, OpenAI и Anthropic. Список правится: один домен или
   диапазон IP в строке (до 200); пустое поле возвращает встроенный список.
3. Доменные зоны страны — напрямую: `.ru`, `.su` и `.рф` для `ru`; `.by` и
   `.бел` для `by`; `.kz` и `.қаз` для `kz`; `.uk` для `gb`; для остальных
   кодов — своя двухбуквенная зона.
4. Готовая категория страны из `geosite` — напрямую, если она есть в
   `geosite.dat` самой панели: `category-ru`, `category-ir` и так далее; для
   Китая `cn` или `geolocation-cn`.
5. `geoip` страны — напрямую, если страна есть в `geoip.dat` панели.
6. Всё остальное — через прокси.

| Формат | Что получает клиент |
| --- | --- |
| **JSON** | Правила в `routing.rules` перед общим правилом, `domainStrategy: IPIfNonMatch`. |
| **Clash / Mihomo** | Правила `IP-CIDR` (`no-resolve`), `DOMAIN-SUFFIX`, `GEOSITE` и `GEOIP` перед `MATCH,PROXY`. Профиль для Clash for Windows — то же без `GEOSITE`. |
| **Happ, INCY** | Профиль маршрутизации в заголовке ответа `Routing`, правила прокси раньше прямых; Happ получает ещё `Routing-Enable: true`. |
| **Shadowrocket** | Файл правил по адресу `<адрес подписки>/shadowrocket.conf`, он предложен на странице подписки: добавьте его на вкладке «Конфигурация» и выберите глобальную маршрутизацию «Конфигурация». Только зоны и `GEOIP`: правила `GEOSITE` в Shadowrocket нет. |
| **Обычные ссылки (Base64)** | Ничего. Список ссылок не может нести правила маршрутизации; приложениям, которые берут только ссылки, нужна JSON-подписка или свои настройки маршрутизации. |
| **AmneziaWG, WireGuard** | Ничего. Эти туннели маршрутизируют только по префиксам IP (`AllowedIPs`), а целая страна — это тысячи префиксов, которые постоянно меняются. |

Профиль маршрутизации, который вы задали для формата сами, в этом формате
главнее. **Профиль маршрутизации JSON** (`subJsonRoutingRules`) заменяет эти
правила в документах JSON и в заголовке `Routing`, профиль маршрутизации Happ —
в заголовке. Свои правила Clash ставятся перед этими правилами и заменяют их,
если содержат собственный `MATCH`. Старое поле правил JSON (`subJsonRules`)
остаётся впереди.

Страна, список и геобазы читаются при запуске сервера подписок, поэтому
изменение начинает действовать после перезапуска панели. Категории сверяются с
базами панели, потому что ядро клиента отказывается от всего профиля, если в
нём названа категория, которой нет в его базе; у клиента с нестандартной
собственной базой категории всё же может не оказаться. Настройка одна на всю
панель: отдельной страны для клиента нет, и панель не угадывает страну по
адресу, с которого запрошена подписка, и не обращается к внешним геосервисам.

### Base64 vs JSON

Тело **Base64** — это просто ссылки для обмена, объединённые через перевод
строки и закодированные в стандартный base64 (переключается через `subEncrypt`).
Тело **JSON** оборачивает каждого клиента в полную клиентскую конфигурацию
Xray — фиксированный каркас (локальные входящие SOCKS/HTTP на 127.0.0.1, DNS, маршрутизация,
policy) плюс исходящее соединение `proxy`, указывающее на входящее. 3x-ui
выдаёт **единый объект конфигурации для одного клиента и массив для
нескольких**, использует плоскую форму `settings` исходящего соединения
(`address`/`port`/`id`, `level: 8`) и удаляет `sockopt` из `streamSettings`.

## Заголовки ответа

Подписки возвращают стандартные заголовки, которые читают совместимые
приложения:

- **`Subscription-Userinfo`** — `upload`, `download`, `total` (байты; `total=0`
  означает без ограничений) и `expire` (Unix-секунды).
- **`Profile-Update-Interval`** — интервал обновления в часах (`subUpdates`).
- **`Profile-Title`**, **`Support-Url`**, **`Profile-Web-Page-Url`**,
  **`Announce`** — необязательный брендинг, отображаемый некоторыми клиентами.

### Ссылка на страницу профиля

В настройках **Подписка → Профиль** поле **Страница профиля** (`subProfileMode`)
управляет ссылкой для всех клиентов подписки:

- **Без ссылки** (`none`, по умолчанию) — заголовок `Profile-Web-Page-Url` не отправляется.
- **Встроенная страница подписки** (`builtin`) — ссылка на встроенную страницу подписки.
- **Свой сайт** (`custom`) — адрес из `subProfileUrl`; если он пуст, заголовок не отправляется.

**После обновления:** если `subProfileMode` ещё не задан, а прежний `subProfileUrl`
пуст или содержит только пробелы, вместо автоматической ссылки на встроенную
страницу теперь используется **Без ссылки**. Существующий непустой пользовательский
адрес сохраняется в режиме **Свой сайт**.

Чтобы вернуть прежнюю ссылку, выберите **Встроенная страница подписки** в этом поле
и сохраните настройки. Эта страница раскрывает URL-адреса подписок и конфигурации
узлов, в том числе для зашифрованных подписок Happ.

## Пользовательские шаблоны страниц

Укажите в `subThemeDir` папку с пользовательским шаблоном информационной
страницы, чтобы оформить HTML-страницу подписки в фирменном стиле. Примечание
для каждого клиента на каждой ссылке полностью шаблонизируется — см.
[Ссылки для обмена → переменные примечаний](/docs/config/share-links#remark-template-variables).

<Callout type="info">
  Разместите сервер подписок за TLS (задайте `subCertFile`/`subKeyFile` или
  [обратный прокси](/docs/operations/reverse-proxy)), чтобы содержимое подписки
  не передавалось в открытом виде.
</Callout>
